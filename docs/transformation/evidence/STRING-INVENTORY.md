> ## ⚠️ CORRECTION — section 1's missing-key figures are a parser artifact, not a finding
>
> **Verified and retracted by the Orchestrator, 2026-08-23.**
>
> This document originally reported **809 keys present in `en` but missing from `el`**, and 814 the
> other way. Both figures are wrong, and the near-symmetry was the tell: two bundles cannot each be
> missing ~800 of the other's keys unless the parser is mis-walking the nesting.
>
> **Key parity is enforced by the TypeScript compiler and cannot drift.**
> `lib/i18n/translations/el.ts:3318` declares `export type TranslationKeys = typeof el`, and
> `en.ts:4` declares `export const en: TranslationKeys = { … }`. A missing key is a type error; an
> extra key is an excess-property error.
>
> Proof, run rather than argued: deleting a single key from `en.ts` produces
> `en.ts(91,5): error TS2741: Property 'insightsShort' is missing in type … but required in type …`.
> `npm run type-check` is green on HEAD, so **the two bundles have identical key sets — 0 missing in
> either direction.**
>
> Everything below this box — Latin contamination, placeholder tokens, longest strings,
> interpolation mismatches, duplicates — was spot-checked and stands. Only the section 1 gap counts
> are retracted. The total key count (~2,730) is consistent with parity and is retained.
