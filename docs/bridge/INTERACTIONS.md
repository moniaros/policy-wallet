# PW-BRIDGE-01 — L0.2 The Interaction Ledger

**Enumerated from code on NEW-UI `1f863b31` (2026-09-06).** One row per path by which one user type causes an effect the other can observe. «Told?» is what the code does today: **visible** (the affected party sees it happened, who did it, when), **passive** (the row appears on a page if they look; nobody tells them), **invisible** (no trace on any surface of theirs), **misleading** (a trace exists but says something else). Half-failure = what the affected party sees when the write succeeds and the trace fails, or the reverse. Nothing here is repaired; every row is Queue B input.

Facts used throughout: `emit()` (`lib/notifications/dispatch.ts`) writes a `notifications` row with `userId` (the RECIPIENT), `eventType`, `title`, `message`, `relatedObjectId` — **no actor column**; the actor exists only if the copy names them. `logActivity` / `activityLog` rows are read by admin pages only (no owner- or agent-facing feed reads `ActivityLog`). Outbound email/push is refused outside production by `lib/outbound/dispatch-guard.ts` (the L0 stub check: NODE_ENV=development → `allowed:false`; a test run throws) — so every harness act below leaves in-app rows only.
